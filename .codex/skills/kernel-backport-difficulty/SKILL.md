# 内核补丁回合难度评分

## 工作流

1. 获取上游补丁、目标内核版本或源码树，以及目标分支的 KABI 约束。只有补丁时先给预评分，明确缺少目标树证据。
2. 在目标树的临时 worktree 执行三方应用或 cherry-pick，记录目标 commit、命令、是否成功及冲突文件/hunk/行数。不要修改用户原始源码树。
3. 使用发行版 KABI 工具或 libabigail 比较符号、函数原型、导出结构体布局和白名单违规。纯文本检出仅作为线索，不能据此判定 KABI 为零风险。
4. 阅读冲突上下文和提交依赖，判断核心路径、锁/生命周期/中断语义、需要补入的依赖提交及 API 适配。不要只按路径或补丁行数下结论。
5. 根据目标架构、配置、启动/运行时和并发回归要求估计最小合理验证成本。
6. 按 [references/scoring.md](references/scoring.md) 的完整字段要求写入证据 JSON，再运行评分脚本。维度字段不全时先补证据，不要用默认值填空。
7. 输出总分、等级、各维度贡献、来源、定位、未知项及降险建议。存在 unknown 或 heuristic 时必须称为“预评分”。

## 命令

先将 `SKILL_DIR` 解析为本 Skill 的绝对根目录，再执行：

```bash
python "$SKILL_DIR/scripts/score_backport.py" \
  --patch /absolute/path/change.patch \
  --evidence /absolute/path/evidence.json \
  --json /absolute/path/score.json \
  --markdown /absolute/path/score.md
```

仅做补丁文本预评分时省略 `--evidence`。不指定输出路径时向 stdout 输出 JSON。`overrides` 仅用于专家复核，必须附原因。

## 评分约定

- 固定权重：冲突 30%、KABI 25%、核心子系统侵入 25%、语义适配 10%、验证成本 10%。
- 各维度先归一化到 0–100，再计算 `总分 = Σ(维度分 × 权重)`；分数越高越难。
- 等级：0–19 极易，20–39 较易，40–59 中等，60–79 困难，80–100 极难。
- 未知维度使用中性分 50 暂算并降低置信度；不得把未知写成零风险。
- 实测冲突/KABI 属于 `observed`，人工语义/验证分析或专家覆盖属于 `manual`，自动路径扫描属于 `heuristic`。
- 报告保留原始测量值、公式、来源和定位。总分等于报告中各加权贡献之和，不得仅凭总分给出合入建议。

## 报告要求

1. 总分、难度等级、置信度及是否为预评分。
2. 五维表格：维度分、权重、加权贡献、状态、来源、关键证据。
3. 最多三项已识别风险及文件/符号/hunk 定位；未知项不得列为主要风险。
4. 未知证据清单和对应获取方法。
5. 最多三条有证据支持的可执行建议。
